# Sealed-core development roadmap

**Current candidate (2026-11-06):** [draft PR #8](https://github.com/levelinglucy/Sealed-core/pull/8) now links verified signed NEW_TICKET requests to atomic core receipts; matching same-key retries can recover proven committed tickets and associated registry scope without duplicate side effects. [Code/test CI 42280404380](https://github.com/levelinglucy/Sealed-core/actions/runs/42280404380): 48/48 Python unit tests plus 9/9 core self-tests on each Python 3.11 and 3.12. **Not merged, tagged or stable.** Existing main retains prior repairs; this is isolated on the reviewable branch.

**Next acceptance:** (1) safe, owner-only audited reconciliation/rollback plan for legacy/unlinked PENDING and non-ticket writes; (2) preserve exact signed scope and no-payload-leak rules in future changes; (3) check trust/platform durability before release. A missing core receipt never proves non-execution. No blind retry, no general exactly-once claim, no change in visibility/network permissions.

**Latest bounded addition:** owner-local `inspect_pending_evidence_local()` now classifies redacted PENDING/core ticket evidence from one encrypted snapshot without changing encrypted state or authorizing an automatic retry. Synthetic regression coverage and runbook added on draft PR #8. [Code+docs CI 42288153350](https://github.com/levelinglucy/Sealed-core/actions/runs/42288153350) passed 53/53 unit tests and 9/9 self-tests on each Python 3.11 and 3.12; final docs-only revision and target-device/power-loss validation remain to check before any promotion. This is *not* reconciliation for legacy/non-ticket writes.

**Downgrade rehearsal completed on synthetic copies (2026-11-06):** `tests/test_downgrade_rehearsal.py` ran pinned historical main code (`6f6e9c67`) only against copied encrypted PENDING stores, proving it duplicates a committed ticket (**1 → 2**) and blindly processes an uncommitted pending request (**0 → 1**). Original encrypted bytes and representative output were preserved. [CI 42296125471](https://github.com/levelinglucy/Sealed-core/actions/runs/42296125471): 55/55 unit and nine self-tests per Python 3.11/3.12. Full Git history is required in CI; no production storage was used. **Old source-only rollback is unsafe.**

**Next acceptance sequence:** (a) exact final documentation CI/readback, (b) evaluate a realistic owner-only reconciliation/audit design for historical and non-ticket PENDING without guessing outcomes or clearing by default, (c) trusted-device and power-loss validation, and (d) an independently reviewable upgrade/downgrade contract. Until then preserve both encrypted state files plus matching vault/output snapshots, block old-code writes while unresolved PENDING exists, leave PR #8 draft/unmerged and record each limitation.
